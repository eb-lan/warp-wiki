## Где хранится содержимое

Исходные тексты расположены в `content/`. Каталог `guides/` содержит руководства, а `reference/` — справочные материалы. Шаблоны находятся отдельно в `templates/`, оформление и скрипты — в `static/`.

Для имени файла используйте короткие латинские слова с дефисами, например `backup-guide.md`. Заголовок самой статьи может быть на русском.

## Параметры статьи

Каждая статья начинается с блока TOML между строками `+++`:

```toml
+++
title = "Название статьи"
description = "Одно предложение о том, что узнает читатель."
weight = 10
toc = true
+++
```

| Поле | Для чего нужно |
| --- | --- |
| `title` | Заголовок страницы и название в меню |
| `description` | Краткое описание для страницы и поиска |
| `weight` | Порядок в разделе: меньшие значения идут раньше |
| `toc` | Оглавление по заголовкам статьи |
| `draft` | При `true` исключает статью из обычной сборки |

В существующих разделах `toc = true` наследуется от `_index.md`, поэтому повторять его в каждой статье не обязательно.

## Новый раздел

Создайте папку в `content/`, например `tutorials/`. Добавьте в неё `_index.md`:

```toml
+++
title = "Практика"
description = "Пошаговые примеры."
weight = 3
sort_by = "weight"

[cascade]
toc = true
+++
```

Теперь добавьте в папку статьи. Раздел и его страницы появятся в боковом меню автоматически. Этот стартовый шаблон выводит разделы первого уровня; для более глубокого дерева можно расширить `templates/navigation.html`.

## Ссылки и изображения

Для ссылок на другие статьи используйте ссылки Hwaro на исходный файл — они учитывают путь сайта на GitHub Pages:

```markdown
[Быстрый старт](@/guides/quick-start.md)
```

Изображения удобно хранить в `static/images/`. При публикации содержимое `static/` копируется в корень собранного сайта. При использовании обычного Markdown указывайте полный путь с префиксом проекта: `/warp-wiki.github.io/images/example.png`.

## Перед публикацией

- Проверьте команды и примеры на практике.
- Объясните ожидаемый результат каждого важного шага.
- Дайте статье понятный заголовок и короткое описание.
- Убедитесь, что в тексте нет паролей, токенов или личных данных.
- Для совместного редактирования используйте pull request: так изменения удобно обсудить до публикации.
